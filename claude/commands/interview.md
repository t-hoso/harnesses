# /interview — 着手前インタビュー(汎用)

設計に限らず、**あらゆる会話・タスク**に使える。実装・調査・執筆・計画・意思決定・
レビューなど、Claude が何かに本格着手する前に、判断の前提を人間と揃えるためのコマンド。

## 基本思想(このコマンドの前提)

- **Claudeの「不確実性」(質問)だけでなく「確信」(決定)も人間の検証対象とする。**
  間違った確信は質問として上がってこない。だから確信の方が、質問よりも事故リスクが
  大きい。ここでは Claude が「確定」と判断した前提・方針・判断こそ最優先で人間に晒す。
- **網羅性はファイルへの全件永続化で担保し、認知負荷は1件ずつの提示で抑える。**
  すべての曖昧点・決定はまずファイルに漏れなく書き出す(網羅性)。人間への提示は
  常に一度に1件だけにする(認知負荷)。この2つを両立させるのがこのワークフロー。

この2点は本コマンドの動作全体を貫く。以降の手順で迷ったら、この思想に立ち返ること。

---

## 入力

`$ARGUMENTS` の先頭トークンを **テーマ名** として扱う(ファイル/ディレクトリ名に使える
短い識別子。例: `refund-flow`, `blog-post`, `db-migration`)。残りを **対象**
(扱う依頼・タスク・問題・議題、参照すべき資料や既存コードのパスや説明)として扱う。

テーマ名が与えられていなければ、まず対象を一言確認してからテーマ名を提案し、合意を得る。
出力先は `docs/interviews/<テーマ名>/` 配下。

作業ファイル:
- `docs/interviews/<テーマ名>/questions.md` — 曖昧点バックログ
- `docs/interviews/<テーマ名>/assumptions.md` — 前提・決定バックログ(+ non-goals)
- `docs/interviews/<テーマ名>/decisions.md` — 承認済み決定の最終記録(軽量な決定記録)

これらは `docs/interviews/_templates/` のテンプレートを複製して作る。テンプレートが
無い環境では、テンプレート内の構造を思い出してその場で同等の雛形を作ること。

> 会話の性質によっては全ファイルが大げさなこともある。その場合でも「確信も検証対象」
> 「1件ずつ提示」の原則は保ちつつ、永続化の粒度は対象の重さに合わせて調整してよい。
> ただし件数を絞る(網羅性を落とす)ことはしない。

---

## フェーズ1:網羅列挙

対象を実際に読み込み(パスが渡されていれば Read/Grep で中身を確認する)、以下を
**上限なく全件** ファイルに書き出す。件数を絞らない。

### (a) 曖昧点 → `questions.md`

「人間に聞かないと確信を持てないこと」。各件に必ず:

- **ID**(`Q001` 形式)
- **質問文**(人間が答えられる具体的な問い)
- **影響度**(高/中/低):間違えた場合の手戻りコスト
- **不可逆性**(高/中/低):後から変更する難易度
- **依存関係**:この質問の答えで自動解決される他の Q/A の ID
- **AIの推奨案と根拠**(**必ず全件に付ける**。「わからないので聞く」で終わらせない)
- **ステータス**(未確認/回答済み/依存解決)。初期値は全件「未確認」

### (b) 確信して置いた前提・決定 → `assumptions.md`

「Claude が確信を持って決めたこと・当然の前提として置いたこと」。**間違った確信ほど
危険**なので網羅する。各件に:

- **ID**(`A001` 形式)/ **決定内容** / **根拠**
- **影響度・不可逆性**(質問と同じ軸)
- **意外性**(高/中/低):「別の合理的な人なら違う選択をしうるか」
  「一般的な選択や人間の期待と異なる可能性があるか」の自己評価
- **依存関係**:上流の Q/A との関連
- **ステータス**(未承認/承認済み/修正済み/依存無効化)。初期値は全件「未承認」

### (c) non-goals → `assumptions.md` 内の独立セクション

「この対応が **意図的に扱わないこと・想定しないケース・スコープ外と判断したこと**」。
**必ず列挙する**。暗黙のスコープ判断を残さない。ID は `N001` 形式。

### 列挙の基準

- **迷ったら questions へ。確信があるものだけ assumptions へ。**
- 「書くまでもなく自明」と思った判断でも、**影響度が中以上なら assumptions に書く**。
  自明だと感じた確信こそ、間違っていたときに誰も気づかない。

フェーズ1の終わりに、各ファイルの進捗表(件数)を埋め、全件書き出せたことを確認する。

---

## フェーズ2:順序付け

- 依存関係を分析し、**決定力の高い質問**(答えると他が芋づる式に決まるもの)を特定する。
- **質問の提示順** = 決定力 → 影響度 → 不可逆性 の降順。
- **決定の提示順** = 意外性 → 影響度 → 不可逆性 の降順。
  ただし **non-goals は決定ウォークスルーの冒頭にまとめて配置**する
  (スコープ認識のズレは他のすべての承認の前提になるため)。

確定した提示順を各ファイルの「提示順」セクションに ID の並びとして記録する。

---

## フェーズ3:質問ループ(1問ずつ)

全質問を解消するまで、以下を1問ずつ繰り返す。

- **質問は必ず一度に1件だけ提示する。複数件の同時提示は禁止。**
- 提示フォーマット:
  - **進捗表示**(例:「質問 残り12件 / 全20件(この後 決定承認 全35件)」)
  - **質問文** / **AIの推奨案と根拠**
  - 選択肢が明確な場合は **番号付き選択肢**
- 人間は **番号・短文・「推奨案でOK」** のいずれでも回答できる。曖昧なら聞き返す。
- 回答を受けたら、次の1問を出す前に必ず:
  1. `questions.md` の該当 Q を「回答済み」に更新し、**回答内容を記録**する。
  2. 依存で自動解決される質問は「**依存解決**」にし、**導出結論**を記録する
     (「Q003 の回答から自動的にこう決まる」)。
  3. 回答が既存の assumptions と矛盾する場合、該当の A を「**依存無効化**」にして
     決定を作り直し、`assumptions.md` を更新する(意外性等も付け直す)。
  4. 回答から新たな曖昧点・決定が派生したら各ファイルに **追加**し、進捗に反映する。
     追加された質問は提示順に差し込む。
  5. 進捗表示を更新し、**次の1問**を提示する。

未確認の質問が残っている限りフェーズ4へ進まない。

---

## フェーズ4:決定ウォークスルー(1件ずつ)

**全質問の解消後**に開始する(未確認・回答待ちの Q が無いこと)。
決定も **必ず一度に1件だけ** 提示する。

提示順は、まず **non-goals をまとめて**(冒頭)、続いてフェーズ2で決めた決定の順。

- 提示フォーマット:
  - **進捗表示**(例:「決定承認 残り30件 / 全35件」。non-goals も件数に含める)
  - **決定内容 / 根拠**
  - **意外性が中以上の場合は「他にありえた選択肢」も併記**する
  - 人間の選択肢を明示:**「承認 / 修正(内容を指示) / 質問に戻す(格下げ)」**
- 回答を受けたら:
  - **承認** → `assumptions.md` の該当 A(または N)を「**承認済み**」に更新し、
    `decisions.md` に決定記録エントリとして追記する(由来 ID・承認日を含む)。
  - **修正(内容を指示)** → 指示どおり決定内容を書き換えて「**修正済み**」にし、
    確定版を `decisions.md` に記録する。修正が下流の決定/質問に影響するなら、
    依存する項目を再評価し、必要なら該当 A の意外性等を付け直す。
  - **質問に戻す(格下げ)** → 人間が「自明ではない、確認したい」と判断した決定。
    該当 A を「**依存無効化**」にし、`questions.md` に新しい Q を追加する。
    フェーズ3は既に終わっているので、**その場でその1問だけ質問ループを回して**
    解消し、結論を反映してからウォークスルーに戻る。
  - いずれの場合も進捗表示を更新し、**次の1件**を提示する。

---

## 完了条件(これを満たすまで先へ進まない)

- `questions.md`:未確認・回答待ちの Q が **ゼロ**(全件 回答済み or 依存解決)。
- `assumptions.md`:未承認の A・N が **ゼロ**(全件 承認済み / 修正済み / 依存無効化)。
- `decisions.md`:承認された全決定と non-goals が最終記録として残っている。

この3条件が揃って初めて「確認フェーズ完了」を宣言する。1件でも未解消なら未完了。
最後に、承認済み決定の要約・スコープ外・残った前提を一言でまとめて人間に提示し、
本来のタスク(実装・調査・執筆など)へ進んでよいか確認する。

---

## 全体を通じた不変則

- **1件ずつ。** 質問も決定も、人間への提示は常に一度に1件だけ。まとめて出さない。
- **全件永続化。** すべての判断はまずファイルに書く。会話の中だけで済ませない。
- **確信も検証対象。** 決定(assumptions)を質問と同格、むしろ優先で人間に晒す。
- **進捗を常に見せる。** 残件数/全件数を毎回示し、網羅の全体像を人間に保たせる。
- **勝手に完了しない。** 完了条件を満たすまで、本来のタスクへ進む提案をしない。
